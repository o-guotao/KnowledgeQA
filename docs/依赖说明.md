### 后端依赖关系图（核心链路）

```
登录      bcrypt(校验密码) → PyJWT(签发 token)
           ↓
CRUD      FastAPI(路由) → Pydantic(校验/序列化) → SQLAlchemy(ORM) → asyncpg(驱动) → Postgres
           ↓                                                         ↑ pgvector(向量类型)
文档上传  python-multipart(解析) → minio(存 MinIO) + SQLAlchemy(记 documents 表)
           ↓
任务执行  uvicorn(ASGI) → sse-starlette(SSE) → httpx(调 DeepSeek)
                                                    ↓
                                                  fastembed(向量召回) → pgvector SQL
                                                    ↓
                                                  pypdf(PDF 提取, 仅 worker)
```

## 几个"为什么是这个不是那个"的说明

### 后端

- **httpx 而非 requests/urllib3**：DeepSeek 流式响应是 SSE 长连接，`requests` 是同步阻塞的会卡住事件循环；`httpx` 原生支持 `async with client.stream()` + `aiter_lines()` 逐行异步消费
- **asyncpg 而非 psycopg**：FastAPI 是异步的，DB 驱动也必须异步，否则每个查询阻塞整个事件循环；`asyncpg` 是协程原生，`psycopg2` 是同步
- **pgvector Python 包**：只是给 SQLAlchemy 提供 `Vector` 类型映射与 `<=>` 运算符的 ORM 表达，真正的向量计算在 Postgres 服务端的 pgvector 扩展里
- **sse-starlette 而非手写 StreamingResponse**：手写要自己处理心跳、客户端断开检测、事件格式化；sse-starlette 封装了这些，且与 Starlette 中间件链兼容
- **fastembed 而非 sentence-transformers**：fastembed 用 ONNX Runtime 后端，安装体积约 200MB（sentence-transformers 拖入 PyTorch 全家桶约 2GB+）；CPU 推理速度更快，符合"虚机部署、轻量"的场景。DeepSeek 没有 embedding API 是必须另选 embedding 方案的根本原因
- **PyJWT 而非 python-jose**：PyJWT 专注 JWT 单一职责，依赖少；python-jose 含 JOSE 全家（JWS/JWE/JWK），本系统只需要 JWT 签发验证，过度

### 前端

- **zod 而非 just TypeScript 类型**：TS 类型只在编译时存在，运行时消失；SSE 事件、REST 响应、localStorage 都是运行时数据，必须用 zod 在运行时校验后才能消费——这是"前端契约"的核心（计划里"用校验库对齐运行时，不要只写类型"那条的直接落地）
- **openapi-typescript 与 zod 并存**：前者从后端 OpenAPI 生成 TS 类型（编译时核对），后者手写但运行时校验——两条独立路径交叉验证契约一致性，任一偏差都能在开发期暴露
- **fetch + ReadableStream 而非 EventSource**：EventSource 不支持自定义 `Authorization` 头，也无法用 `AbortController` 停止生成；fetch 流式读取 SSE 行 + 手动解析是本系统 SSE 客户端的唯一可行选择
- **react-markdown + remark-gfm 而非 dangerouslySetInnerHTML**：助手回答是模型生成的 Markdown，必须解析渲染而非直接插入 HTML（XSS 风险）；react-markdown 默认转义 HTML，安全
- **class-variance-authority + tailwind-merge 而非 styled-components/emotion**：CSS-in-JS 运行时开销大，且与 Tailwind 生态冲突；CVA 是编译时变体定义，配合 tailwind-merge 处理 className 冲突，零运行时开销
