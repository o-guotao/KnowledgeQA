# 系统设计二：知识库问答（RAG）（STAR）

## Situation

公司制度、产品 FAQ、安全规范散落在各文档中，员工查找成本高；通用大模型不知道内部知识，直接回答会编造。

## Task

构建最小可用 RAG 闭环：文档上传 → 切分 → 向量化 → 召回 → 带引用的回答，并要求回答可溯源、权限隔离、效果可量化。

## Action

**入库链路**：原文存 MinIO → `ingest_document` 任务入队 → worker 提取文本（pypdf/utf-8）→ 按句边界切分（默认 512/64）→ BGE-small-zh 批量 embedding（32/批）→ chunks 表（vector(512)，IVFFlat 余弦索引）事务写入。

**查询链路**：问题 embedding → `WHERE user_id = ? ORDER BY embedding <=> ? LIMIT 5`（权限过滤下推 SQL）→ citation 事件先下发 → 召回块包裹 `<<<RETRIEVED_DATA>>>` 注入 prompt → 流式回答 → 前端角标点击按 chunk_id 回查原文高亮。

**关键决策**：

1. ** pgvector 而非独立向量库**：数据量 <100 万 chunk，HNSW 索引（建表即生效，小数据集召回也准确，避开 IVFFlat 在空表上聚类失效的问题）；少一个组件，事务与权限过滤天然复用 Postgres。
2. **切分按句边界**：窗口后 1/3 内找句读/段落边界，避免切断语义；chunk_size/overlap 入库时固化到 documents 表，保证同一文档切分一致、可重放。
3. **本地 embedding**：DeepSeek 无 embedding API，BGE-small-zh（ONNX，CPU 可跑）零额外密钥与费用，维度 512 与索引配置一致。
4. **注入防护双层**：检测层正则命中告警留痕；约束层分隔符 + 系统提示声明召回内容为数据。
5. **引用是数据而非后处理**：citation 在召回时即确定（SSE 独立事件），不依赖模型输出的角标文本，保证可点回原文。

## Result

30 条评测问句驱动迭代；调整 chunk_size/overlap 前后，召回命中率与回答正确率可升可降（见评测对比表），证明闭环真实有效而非演示摆设。

## 四问

- **数据**：documents（原文指针+切分参数+状态）与 chunks（文本+偏移+向量）分表；用户删除文档级联删 chunks，原文从 MinIO 移除。
- **失败**：提取/embedding 失败 → 文档 failed 可重传重放；召回异常 → 降级为空召回并明确告知「未检索到资料」，不编造。
- **费用**：embedding 本地零成本；费用全部来自问答侧 token，见 01。
- **评测**：30 条问句，召回命中率（citation 含 gold_doc）+ 回答正确率（关键词命中）；`run_eval.py --compare` 输出前后对比。
