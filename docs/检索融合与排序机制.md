# 检索融合与排序机制（BM25 / 向量 / 重排）

> 结论先行：本项目**没有可配置的"权重"参数**。向量与 BM25 采用 **RRF 排名融合（两路等权）**，
> 重排是**覆盖式精排**而非加权叠加。以下为代码级说明（源：`backend/app/services/rag.py`、
> `bm25_index.py`、`rerank.py`、`config.py`）。

---

## 一、整体链路

```
用户问题
  │
  ├─[1] embed_query(q)                    向量化（fastembed BGE / openai / hash 降级）
  │
  ├─[2] 双路召回（各自取 candidate_k 条）
  │      ├─ 向量路：pgvector cosine_distance（pg）/ Python 余弦（sqlite）
  │      └─ 关键词路：BM25 内存索引（默认，jieba+rank_bm25）
  │                   └ 回退：tsvector ts_rank（pg）/ LIKE（sqlite）——依赖缺失或 BM25_ENABLED=false
  │
  ├─[3] RRF 融合（仅当 HYBRID_SEARCH_ENABLED=true）→ 等权排名融合，取 candidate_k 条
  │
  ├─[4] 重排（仅当 RERANK_ENABLED=true）→ cross-encoder 逐对打分，按新分数取 top_k
  │
  └─[5] 父子块上下文解析：命中 child 块 → 取其 parent 块内容进 prompt（不参与排序）
```

## 二、关键参数

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `RAG_TOP_K` | 5 | 最终进入 prompt 的块数（也可由前端按会话覆盖） |
| `HYBRID_SEARCH_ENABLED` | true | 是否启用向量 + 关键词 RRF 融合 |
| `BM25_ENABLED` | true | 关键词路用 BM25（内存索引）；false 则回退 tsvector/LIKE |
| `RERANK_ENABLED` | 生产 true / 本地 false | 是否启用 cross-encoder 重排 |
| `RERANK_MODEL` | `BAAI/bge-reranker-base` | 重排模型 |
| `RERANK_CANDIDATE_MULTIPLIER` | 4 | **候选放大倍数**：candidate_k = top_k × 4（仅开启重排时） |

**候选放大是链路里最接近"权重"的设计**：不开重排时两路各取 top_k 条直接融合；开重排时两路各取
top_k×4 条（如 top_k=5 → 40 条），给重排器更大的挑选池。

## 三、RRF 融合：为什么没有权重

实现（`rag.py::_rrf_fuse`）：

```python
for rank, item in enumerate(vector_results):
    scores[item.chunk_id] += 1.0 / (60 + rank)
for rank, item in enumerate(keyword_results):
    scores[item.chunk_id] += 1.0 / (60 + rank)
```

- 公式：`score(chunk) = Σ_路 1 / (60 + rank)`，RRF 常数 **k=60**，rank 从 0 起（第 1 名贡献 1/60）
- **两路贡献完全相等**：向量第 1 名与 BM25 第 1 名各得 1/60，不存在 `w_vec` / `w_bm25` 权重
- 只用**排名**不用**分数**，因此无需归一化：向量余弦（-1~1）、BM25（无上界）量纲不同也能直接融合，
  这是 RRF 相对"加权分数和"的核心优势（论文：Cormack et al., 2009）
- 同时命中两路的块会累加两项 → 天然获得"双路共识"加成

## 四、BM25 关键词是怎么提取的（分词细节）

BM25 的"关键词"= **jieba 分词后的全量 token 列表**，不是 TF-IDF / TextRank 式的"抽取 N 个关键词"。
实现（`bm25_index.py::_tokenize`）：

```python
_CJK_RE = re.compile(r"[一-鿿]")
_ALNUM_RE = re.compile(r"[A-Za-z0-9]")

def _tokenize(text: str) -> list[str]:
    """jieba 分词 + 清洗：小写、去空白、去纯标点（保留含中文或字母数字的 token）。"""
    tokens = []
    for tok in jieba.lcut(text.lower()):
        tok = tok.strip()
        if tok and (_CJK_RE.search(tok) or _ALNUM_RE.search(tok)):
            tokens.append(tok)
    return tokens
```

处理流程：

| 步骤 | 处理 |
| --- | --- |
| 1 归一化 | `text.lower()`（英文统一小写） |
| 2 分词 | `jieba.lcut`（精确模式，内置词典；中文按词切分，英文/数字保持整体） |
| 3 清洗 | 去首尾空白；丢弃纯标点/空白 token（保留"含中文 或 含字母数字"的 token） |
| 4 用途 | 建索引：`corpus = [_tokenize(chunk.content)]`；查询时：`_tokenize(query)` → `bm25.get_scores(tokens)` |

关键特征：

1. **不过滤停用词**——"的/了/是"也进索引，靠 BM25 的 IDF 天然降权（高频词权重趋近 0），
   `search()` 中 `score <= 0` 的候选直接截断
2. **不限 token 数量**——整段 chunk 全量分词（对比数据库回退路径最多 8 个）
3. **IDF 全库统计**——所有用户 + 团队空间的 child 块共同参与，用户隔离在取 top 结果时过滤
4. **无自定义词典**——专业术语/编号会被切开：`METRIC-0012` → `METRIC` + `0012`（`-` 被清洗）。
   两段仍能命中所以通常有效；若要求**整串精确匹配**，需 `jieba.add_word("METRIC-0012")`
   或在清洗阶段补充正则切分
5. **语料与查询共用同一分词器**——保证 token 空间一致，这是 BM25 生效的前提

与数据库回退路径的差异（`BM25_ENABLED=false` 时走 `rag.py::_keywords`）：

| | BM25 路（默认） | 数据库回退路 |
| --- | --- | --- |
| 分词 | jieba 词粒度（含停用词） | 正则 `[一-龥]{2,}\|[A-Za-z0-9_\-]{2,}`，≥2 字符，**最多 8 个** |
| 匹配方式 | 全库 BM25 打分排序 | pg：tsvector `@@` 全文检索；sqlite：LIKE 子串 |
| 编号类 | 切成片段（METRIC / 0012） | 保留完整串（含 `-`） |

> 两条路对"编号/专有名词"的机制不同，这是评测中心 `hybrid`（tsvector，Recall@5 70%）与
> `hybrid_bm25`（BM25，Recall@5 100%）两组差异的底层原因之一。

## 五、重排：覆盖而非加权

实现（`rerank.py::rerank`）：

```python
scored = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
return [c for c, _ in scored[:top_k]]
```

- cross-encoder 对「问题 + 块内容」逐对打分，**完全用新分数重排**，RRF 分数被丢弃
- 不是 `final = α·rrf + β·rerank_score` 的加权混合——没有 α/β
- 候选数 ≤ top_k 时直接返回（不加载模型）；模型不可用/异常时**降级为粗排顺序截断**并记日志
- 定位：粗排（快、排序粗糙）→ 精排（慢、准），把相关块从第 8~15 位提到前 3

## 六、实测效果（评测中心数据）

内置样例 30 题（chunk 128/32，真实 BGE embedding）：

| 配置 | Recall@1 | Recall@5 | Recall@10 | MRR | 召回耗时 | 重排耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| baseline（纯向量） | 16.7% | 70.0% | 86.7% | 0.406 | 12.3ms | - |
| hybrid（向量+tsvector 关键词） | 23.3% | 70.0% | 86.7% | 0.470 | 12.8ms | - |
| hybrid_bm25（关键词路换 BM25） | 36.7% | **100%** | 100% | 0.596 | 28.9ms | - |
| hybrid_bm25_rerank（+重排） | **50.0%** | 83.3% | 100% | **0.651** | 24.0ms | 72.0ms |

**读法**：
- **BM25 贡献召回率**：Recall@5 70% → 100%，代价是召回耗时 12.8ms → 28.9ms（+16ms）
- **重排贡献排名质量**：MRR 0.596 → 0.651、Recall@1 36.7% → 50%，代价 +72ms/次
- 注意 rerank 后 Recall@5 反而 83.3%（<100%）：重排把个别正确块挤出了 top5 但整体更靠前——
  这正是"Recall 与 MRR 需一起看"的原因；若在意 top5 完整性，可提高 `RERANK_CANDIDATE_MULTIPLIER`
  或调低重排模型温度类参数（当前模型无此参数，需换模型）

## 七、参数调优建议

| 目标 | 动作 |
| --- | --- |
| 专有名词/编号类召回差 | 确认 `BM25_ENABLED=true`（对 "METRIC-0012" 类查询提升显著） |
| 答案引用位置靠后、LLM 注意力弱 | 开 `RERANK_ENABLED=true`（MRR 提升最直接） |
| 重排后 top5 丢块 | 提高 `RERANK_CANDIDATE_MULTIPLIER`（4 → 6/8），成本是重排耗时线性上升 |
| 延迟敏感 | 关重排（省 ~72ms/次）；BM25 召回耗时随库增大上升，观察 `online-stats` 的 `avg_recall_ms` |
| 编号/术语必须整串命中 | 为 jieba 加自定义词典（`jieba.add_word("METRIC-0012")`，索引构建前调用），或在 `_tokenize` 清洗阶段用正则补充切分 |
| 团队空间文档参与度 | 团队可见性与融合无关，但会扩大候选池（见 `documents-api.md` 团队空间一节） |

## 八、如需真正的加权融合（改造方案）

当前实现刻意不做权重（RRF 的优势即免调参、免归一化）。若业务确需偏向某一路，按代价从低到高：

**方案 A：加权 RRF（最小改动，推荐）**

```python
W_VEC, W_BM25 = 1.0, 1.5   # BM25 偏重示例
scores[cid] += W_VEC  / (60 + rank)   # 向量路
scores[cid] += W_BM25 / (60 + rank)   # 关键词路
```

- 改动点：`_rrf_fuse` 增加两个权重参数，从 settings 读取（新增 `RRF_WEIGHT_VECTOR` / `RRF_WEIGHT_BM25`）
- 优点：保持免归一化、行为可预测；缺点：多两个需调参的旋钮（须用评测中心验证不退化）

**方案 B：分数归一化后加权（改动大，不推荐）**

- 需对两路分数做 min-max / z-score 归一化，再 `α·norm(vec) + (1-α)·norm(bm25)`
- 缺点：BM25 分数无上界、分布随语料变化，归一化不稳定，且丧失 RRF 的鲁棒性

**方案 C：重排分数混合**

- `final = β·rerank_score + (1-β)·rrf_score`，保留粗排信息
- 适用场景：重排模型与领域不匹配时做"保险混合"；需评测验证，否则易引入噪声

> 任何权重改动都必须先经评测中心跑 4 组配置矩阵对比（`docs/功能规划.md` 决策原则：无指标不合并）。
