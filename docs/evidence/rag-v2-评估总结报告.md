- 评估日期：2026-10-12
- 评估集：`backend/eval/dataset/questions_v2.jsonl`（50 题：factual 41 / list 2 / summary 2 / comparison 5；难例 40%；多文档题 5）

## 二、逐项结论

### 检索参数
- **混合检索必开（iter02 消融证据）**：关闭后召回 -4pt、MRR -0.090，并传导到生成层（答案相关性 -3.2pt、上下文召回 -4.7pt）。hybrid+BM25 是基线正确配置。
- **top_k=5 优于 10（iter01）**：召回已饱和，top_k 翻倍只让精准率减半（26%→13%），忠实度还略降（噪音进 prompt）。
- **RRF k 不敏感（iter04）**：60→30 全部指标不变，本语料规模下无需调。

### 索引/切分参数
- **overlap 64→128 是全场唯一"全赢"变更（iter07）**：精准率 +4pt、MRR +1.3pt、答案相关性 +1.8pt、上下文相关性 +5.2pt，无任何指标下降。
- chunk 256（iter05）升精准率/上下文相关性但降 MRR；chunk 1024（iter06）相反。512 仍是平衡点。
- 父子块（iter08）：MRR +2.5pt、忠实度全场最高（0.988），但精准率与答案相关性略降——父块带入更多上下文有利于忠实，但稀释了相关性。

### 查询处理
- **L2 启发式（iter09）是零成本小胜**：精准率 +1.2pt、答案相关性 +1.2pt、上下文相关性 +3.9pt，MRR 无损。
- **L4 LLM Router（iter10）精准率/上下文相关性全场最高**（+9.6pt/+11.5pt），忠实度次高；代价是 MRR -3.2pt 与每查询一次额外 LLM 调用。
- **MRR 损失已归因并调优**（详见 `rag-v2-router-启用建议.md`）：损失全部来自 factual→3 缩小 RRF 融合池致 3 道双事实题首命中后移（分类准确率 100% 无关联）；factual 映射调至 4（iter13）后 **MRR 恢复基线水平且精准率/上下文相关性仍正增益**，建议按「L4 + factual=4」启用。

### 生成参数
- **注入块数 5→3（iter11）**：上下文相关性 +14pt（噪音减半），但答案相关性 -2.6pt、上下文召回 -2.7pt（覆盖不足）。维持 5。
- **简洁 prompt（iter12）**：忠实度 +0.8pt、答案相关性 -0.6pt，基本中性。维持默认 prompt。

## 三、建议采纳的配置

在现默认配置基础上叠加两个无代价变更（**组合验证 best-combo 已确认无负面交互**）：

```
CHUNK_OVERLAP=128        # iter07：全指标不降，精准率/MRR/相关性齐升
top_k 路由=L2 auto_top_k  # iter09：零成本小胜（L4 Router 见下）
```

组合轮（best-combo）vs 基线：召回率持平 100%，精准率 +5.5pt、MRR +1.3pt、
忠实度 +0.6pt、答案相关性 +1.2pt、上下文相关性 +6.9pt、上下文召回持平——**7 项指标 5 升 2 平 0 降**。

可选（story-1008 验收口径）：开启 `llm_router_enabled` 并将 `_CATEGORY_TOP_K["factual"]` 从 3 调为 4——MRR 与基线持平，精准率 +1.6pt、上下文相关性 +3.2pt，其余指标不回退（依据 iter13 与归因分析，见 `rag-v2-router-启用建议.md`）。

## 四、限制与说明

1. **召回率天花板**：新集基线召回即 100%（与旧集历史结论一致，见交叉验证行），区分度主要靠精准率/MRR/生成层指标。后续可加多跳/跨文档更难题。
2. **iter03-rerank 无效**：reranker（BAAI/bge-reranker-base 1.06GB ONNX）本机加载失败（bad allocation，疑内存不足），按系统设计降级为粗排，该轮不代表 rerank 真实效果，需在内存充足环境重跑。
3. **judge 口径**：judge 已经 17 题人工抽检校准（`rag-v2-judge校准记录.md`）；忠实度为从严口径，逻辑蕴含未明述的论断可能判不支持。
4. **生成模型单一**：iter13（换生成模型）未执行，可在 `--custom` 下用 `--set gen_model=<model>` 补测。
