# PRD — 滚动叙事作品集展示页（scrollytelling）

## 1. 背景与目标

做一个**设计师作品集介绍**的单页站点。核心交互是**滚动驱动视频播放**：向下滚 = 主视频前进，向上滚 = 主视频倒放。用户不是在「看视频」，而是在**用手滚动去"搓"出一条叙事**。

预期产出：一个**纯 HTML + CSS + JavaScript、零框架**的独立静态页面。

### 为什么现在做 / 素材现状（重要）

| 素材 | 状态 | 用途 |
| --- | --- | --- |
| `首屏视频.mp4` | **已到位** | 首屏，**鼠标位置擦洗时间轴**（v2，见 §3.2）。第 2 轮期间以 `media/video.mp4` 落地，经用户确认后更名为 `media/intro-loop.mp4`。实测 10.08s / 1280×720 / H.264(avc1) + AAC 带音轨 |

## 2. 视频叙事拆解（3 个关键节奏点）

> 时间区间基于分镜帧与素材命名推导，属**默认值**，真实 MP4 到位后需按实拍内容校准。
> 默认主视频时长 `fallbackDuration = 30s`（见 `showcase.js` 的 `CONFIG`）。
>
> **注意：下表的秒数是按 30 秒假设写的。代码里三段是按占全长比例切分的**
> （`CONFIG.beatCuts = [0.30, 0.70]`），所以你换成 10 秒或 60 秒的主视频，
> 三段依然铺满全长、不会漏段。视频多长，下面这三个区间就等比缩放多少。

分镜顺序由 `start → computer → card → end` 命名与画面内容确定，对应 `示例.jpg` 顶部导航的「作品文件夹 / 作品预览 / 无限可能」，四张画面各占一段、无重复。

## 3. 三段式切换逻辑（硬性要求）

| 滚动进度 `p` | 生效段 | 播放方式 |
| --- | --- | --- |
| `p === 0` | **intro** | **不 autoplay、不 loop**；由**鼠标位置擦洗** `currentTime`（见 §3.2） |
| `0 < p < 1` | **main** | **不 autoplay**，由滚动驱动 `currentTime` |
| `p >= 0.98` | **outro** | **无视频**，静态图 `beat-3.jpeg` 淡入 |

- 三段**同时渲染在 DOM 里**，用 `opacity` 控制显隐；`0.5s` fade 过渡，禁止硬切。
- 两路 `<video>` 一律带 `playsInline`、`preload="auto"`、`muted`。
- `0.98 – 1.0` 区间 outro 淡入叠在 main 最后一帧之上，属**预期行为**。

### 已确认的设计偏离（用户决定，非疏漏）

**偏离 1 — outro 不用视频**。素材只提供 2 个 mp4（首屏 / 主视频），三段式需要 3 段。用户选择让 **outro 只显示静态图**，于是页面只需 **2 路视频解码**。若日后要补独立第三段视频，在 `index.html` 的 outro stage 内加一个 `<video>` 即可。

**偏离 2 — intro 不再 `autoplay loop`**（v2 需求，覆盖原 brief）。原 brief 写的是 `intro-loop (autoplay loop muted)`，但用户明确要求「首屏人物跟随鼠标移动」且选定实现为**鼠标位置擦洗时间轴** —— 一个被鼠标接管时间轴的视频不可能同时自动循环。二者只能取一，**以鼠标擦洗为准**。

**偏离 3 — 背景恒定，不再是「三段视频各自的背景」**（v2 需求）。原设计让 main 段用 3 张分镜 poster 交叉淡入做缺失兜底，这会让背景随板块变化。用户要求背景保持不变，故改为**一张固定背景贯穿全站**（见 §3.3）。
> **v6 又推翻了这一条**：用户改为要求逐节背景（个人简历 / 作品文件夹 / 无限可能各一张分镜图）。
> 本条保留备查，现行需求见 §3.3 与 §3.5。注意这是**第二次**改「背景恒不恒定」，
> 而两次都不是疏忽：v2 要稳定感，v6 要每一节有自己的画面。

### 3.2 首屏鼠标擦洗（v2）

首屏视频素材是「人物上下左右看」。鼠标位置直接驱动其 `currentTime`：

- 鼠标横向位置 → 归一化 `0..1` → `intro.currentTime = x01 × intro.duration`
- 鼠标纵向位置 → 归一化 `-0.5..0.5` → 叠加一个极小的 `translateY`（±8px）做触感反馈
- 鼠标静止 → 画面**静止在对应帧**（不播放、不循环）
- 鼠标尚未移动过 → 人物保持**初始朝向待机**，不因为「鼠标恰好停在屏幕正中」而停在片子中间那一帧
- **触屏无鼠标** → 回退为 `autoplay loop`（否则首屏完全死住）
- `prefers-reduced-motion` → 回退为 `autoplay loop`

**离开首屏时的回正（v3）**：

- 滚轮一旦把 `p` 推出首屏，鼠标**立即交出**控制权，人物**主动回到初始朝向**，再淡出、由下一段接管
- 回正与淡出**重叠**进行（不是先回正完再淡出）。严格串行会让每次开始滚动的响应晚约 0.4s，
  而这段时间 main 视频已经随滚动在身后推进 —— 滚动与画面会脱节
- 回正速度用独立的 `CONFIG.intro.resetEase`（0.26），比跟手阻尼（0.12）快：
  它必须落在 `0.5s` 淡出**之内**才看得见（60fps 下 30 帧是硬上限）
- 回正到哪一帧由 `CONFIG.intro.resetAt`（占总长比例，默认 0 = 片头）决定 ——
  中性朝向在素材的哪一帧由实拍决定，不写死
- 回正完成后**停止写入** `currentTime`（与主视频 `applied` 同一纪律：静止时零 seek）

两个轴到底怎么映射，取决于真实素材的拍法（线性扫视 / 3×3 网格）。默认按**线性横向扫视**实现，映射参数集中在 `CONFIG.intro`，素材到位后按实拍重调。

### 3.3 背景：恒定底图 + 逐节分镜图（v2 → **v6 推翻**）

> **v6 变更（用户明确要求，覆盖 v2）**：v2 要求「全站背景恒定」，v6 改为**逐节背景** ——
> 个人简历用 `intro.jpeg`、作品文件夹用 `beat-1.jpeg`、无限可能用 `beat-3.jpeg`（带下坠揭示）。
> 用户在提问中被明确告知这与 v2 的「恒定」直接冲突、且 v2 之所以裁出净墙面正是因为
> 「人物重影」，仍选择「确认覆盖，直接用整图」。详见 §3.5。
>
> **一处 v2 没写、v6 必须写清的后果**：这几层背景在 `.backdrop` 内部，也就是压在
> **影像（`z-index` 1）之下**。`main.mp4` 一旦到位，四个主段都会被它整屏盖住，
> 分镜背景届时只在视频缺失时才看得见。这是「分层正确」的代价，不是遗漏 ——
> 要让背景盖过视频，得把 `.stage` 与 `.backdrop` 的层序整个倒过来，那是另一个决定。

v2 原文（保留备查）：

- 背景取自**分镜里那面青灰墙**，从 `beat-1.jpeg` 裁出净墙面区域（`x 0–1300, y 60–790`，1300×730，约 16:9），存为 `media/bg-wall.jpeg`。
- `position: fixed`，`object-fit: cover`，**全站恒定不变**，不随板块切换、不随滚动位移。（**v6 已推翻**：它现在是「没有指定分镜图的那两节」的底图，见 §3.5）
- 之所以要裁切而非直接用现成分镜图：四张分镜都把人物画在右侧，直接当背景会让**人物与 main 视频里的人物重影**。（**v6 已推翻**）
- 参考图（`示例.jpg`）**只取文字排版语言**，不取它的背景处理（`示例.jpg` 的背景是一帧视频画面）。但**左侧压暗渐变保留原样**（用户决定）—— 它服务的是文字可读性，与"背景用哪张图"无关。

### 3.4 鼠标波纹层（v4）

用户原话：「缩小影响范围、靠近鼠标的波纹更细、点击时向外扩散，去掉黑色拖尾。」

四条都是**参数/观感要求**，落到实现上必须各有一个可断言的量，否则在无浏览器环境下无法验收：

| 要求 | 落成的量 |
| --- | --- |
| 缩小影响范围 | 可见半径 `influence = 160px`；包络 `(1 − u²)²` 在 `u = 1` 处归零 |
| 靠近鼠标的波纹更细 | 环距随半径线性增长：光标处 16px → 边界处 56px；描边 0.8px → 2.0px |
| 点击时向外扩散 | 每次点击发 **2 圈**、错开 140ms，半径 `easeOutCubic` 扩张到 `influence` |
| 去掉黑色拖尾 | 加色混合 + 每帧全清屏 + 环境场无状态 + 点击环有限寿命 |

**两个已定的岔路**（提问后由用户选定）：

1. **画光晕细环，不做折射扭曲。** 折射（真的扭曲底下画面）观感更"水"，但 `file://` 下 WebGL 读本地图片会抛 `SecurityError`，直接丢掉"双击即开"这个属性；且全屏视频每帧重新采样会和已有的擦洗 rAF 抢帧预算。**「黑色拖尾」本身就是反馈缓冲式折射实现的典型伪影**（上一帧位移量留在缓冲里越积越黑），改用加色混合后这类伪影在结构上不可能出现。
2. **加在影像之上、文字之下**（`z-index: 4`，薄纱在它下面取 3）。**不是**加在 `.backdrop` 上 —— 因为三个 stage 全是 `position: fixed; inset: 0` + `cover` 满屏铺满，墙面只在 `main.mp4` 缺失时才露得出来，加在背景上等于看不见。

   > 层号在 v5 被**对调过一次**（波纹 3→4、薄纱 4→3）。原先的排序理由写的是「波纹若盖在薄纱上，等于把文字可读性交给动效负责」—— 那句话把薄纱当成了文字层，是错的：薄纱只是对影像的一层处理，属于「影像」那一侧；真正要护的文字在 `z-index` 6，波纹无论在 3 还是 4 都盖不到它。而薄纱左侧压暗到 82%，波纹压在它下面会被吃掉约 5 倍亮度，光标常去的左半侧恰好最暗。`design.md` §12.2 的表格与理由同步更正。

**为什么两条结论都要写进 PRD 而不是只写进 design.md**：它们都是用户可见的行为约定（效果加在哪、长什么样），不是内部实现细节。"加在背景上"这个字面理解会直接做错，必须留在需求文档里。

### 3.5 逐节背景 + 文件夹开合 + 下坠（v6）

用户原话（保留错字，含两处拼写错误：`jepg` / `fodler`）：

> 个人简历背景使用intro.jepg  作品文件夹背景使用beat-jepg,左边排版使用fodler.png,点击后弹出beat-2.jepg替换左边内容，特效为弹出过渡效果，无限可能背景使用beat-3.jepg,活动到这也一个下坠的效果展示出这个图.

**原文里 `beat-jepg` 少一个数字**，靠猜会做错一整张图。已用证据定下而不是取最像的那个：读 `media/作品示例排版.png`（用户自己的面板设计稿），其底图是绿灰墙 + 右下角坐在棕色扶手椅上抱 MacBook 的贴纸脸小孩 —— 与 `beat-1.jpeg` 逐项对上。故取 **`beat-1.jpeg`**。

三个决策点都用 `AskUserQuestion` 问过，用户的选择：

| 决策点 | 选项 | 用户选择 |
| --- | --- | --- |
| 「点击后弹出 beat-2 替换左边内容」 | 封面→内页换整图 / 整图当底衬保真文本 / 只让卡片弹出 | **封面→内页，换成整图** |
| 「下坠」是什么 | 滚动进度驱动 / 一次性播放 / 整节下沉 | **滚动进度驱动：图从上方坠入并停住** |
| 逐节背景 vs v2 的恒定背景 | 确认覆盖 / 整图+暗化薄纱 / 仍用净墙裁剪 | **确认覆盖，直接用整图** |

**逐节背景的落法**：背景分两层 —— `.backdrop` 的恒定底图，其上的 `.backdrop__scene` 按节切换。
`data-scene` 与 `data-copy` **取值域相同**（`'0'` / `'1'` / `'3'`），所以「哪一节用哪张图」只在 `index.html` 里出现一次，JS 不认识任何图片名。
没给层的两节（初次见遇 / 作品预览）自然露出底图 —— **层数少于节数是这个设计成立的条件，不是漏写**。
三层都挂在 `.backdrop` 内部而不是另开一个 `fixed` 层：z 序是被「严格递增」断言锁住的（背景 0 < 影像 1），要插在 0 与 1 之间就得用小数，而 `z-index` 不接受。

**下坠的落法**：位置由滚动进度**现算**（`sceneDropY(p, 该节区间)`），不是播一次定时动画 ——
倒着滚会原样升回去、停在中间就停在中间、静止时零写入，与主视频的 `applied` 是同一套纪律。
曲线取 `easeInCubic`（前段慢、后段快 = 越落越快）；落点必须**精确**是 0，不是「趋近于 0」。

**文件夹开合**：内容区两个状态 —— 封面 `folder.png`（合着的文件夹）→ 点击弹出内页整图 `beat-2.jpeg`，回弹曲线做「弹出过渡」。
两类动作刻意分开：**开合**落在内容区自己身上（提示原文「开合」），**收起面板**才是「点空白栏 / ESC」。

**这一版唯一真的牺牲掉的东西**：内页成了位图，卡片正文**不再可选中**。用户在被明确告知这个代价后选了它。
补偿措施（不是等价替换，是一道防线）：三段卡片原文仍留在 HTML 里、挂在 `.sr-only` 上 ——
读屏念得到、`Ctrl+F` 搜得到。断言因此从「必须是可选中真文本」**显式放宽**为「原文必须仍在文档里」，
并在断言旁边写明这是放宽、不是失守后的追认。

### 3.6 v5 交付里修掉的一个真缺陷（v6 一并修）

文件夹面板原先是 `inset: 0` + `pointer-events: auto`，而它是 `z-index: 6`、顶栏是 `5`。
面板半透明，所以那五个导航**看得见却点不到** —— 点任意一个都被面板吃掉，
走 `closePanel()` → `goToSection(3)`，人直接被送到「作品预览」。同一片过宽的可点区还意味着
点 `folder.png` 前板也会收起面板，而提示写的是「点击空白**栏**」。

修法：面板本身改为 `pointer-events: none`，可点区只留给两处真正是「东西」的地方 ——
内容区（= 提示里的「空白栏」）与收起按钮。这同时修掉了「点文件夹前板也收起」这个不一致。
`v6_teeth.js` 里有一条反向验证专门复现这个缺陷：把面板改回 `auto`，对应断言必须变红。

## 4. 排版语言与文案应用

先分析 `frontend/assets/示例.jpg` 的排版语言，再把同一套语言**逐段套用到上面 3 条文案**上。

### 4.1 参考图排版语言拆解

| 维度 | 结论 |
| --- | --- |
| **字体** | 西文主标题：**超粗压缩无衬线 + 全大写**（Anton / Archivo Black 一类），字重对比拉到极致；西文小字：无衬线大写 + 大字距（`0.18em`）；中文：无衬线常规字重，绝不加粗到与主标题争抢 |
| **字号层级** | 主标题 ≈ `clamp(56px, 9vw, 120px)` / `line-height 0.92`；区块小标题 ≈ 24–32px 全大写；eyebrow 与描述 ≈ 14–15px。**比例约 7:2:1**，靠数量级差制造张力 |
| **对齐** | **非对称双栏**：主标题块居左、紧贴左边界；说明文字块右对齐贴右边界。顶部导航为 logo 左 / tab 中 / tagline 右的**三栏**。中央只有 `SCROLL TO EXPLORE` 一句居中 |
| **颜色** | 背景 = 暗调青灰影像（`#3a4238` 系，非纯黑）；文字 = 奶白 `#EDE7DC`（非纯白）；强调色 = 暖沙金 `#E8A33D`；全站**无纯黑无纯白** |
| **装饰元素** | 药丸形描边 CTA 按钮 + 圆形箭头 icon；激活态 tab 用**下划线**（非背景块）；屏幕底部**通栏细进度条**；左 `01 / INTRO 初次见遇`、中 `SCROLL TO EXPLORE` + 下箭头、右 `00:00 / 00:10 暂停互动` |
| **整体气质** | 极简、低信息密度、**呼吸感强**。张力全部来自「巨大字号 vs 大量留白」和「暗色影像 vs 暖白文字」，不靠装饰堆砌 |

### 4.2 套用规则（三段通用，只是文案不同）

每段文案固定由 4 个排版槽位组成，**全部还原参考图**：

1. **eyebrow** — 大写无衬线 + `letter-spacing .18em`，暖沙金，如 `01 / FIRST MEETING`
2. **主标题** — 超大号压缩无衬线全大写，奶白，两到三行硬换行（对应参考图 `DESIGN / WITH / FEELING.`）
3. **描述** — 中文正文，`15px / line-height 1.9`，奶白 85% 不透明度
4. **CTA** — 药丸描边按钮 + 圆形箭头，**仅首屏出现**（v3 更正：原文写的「仅节奏点 1」是 v1 残留，与 design.md §9 及实现相冲突；且 CTA 自身文案「先认识我，再看作品」明显呼应首屏的「别急着看作品，先认识一下」，搬到节奏 1 会语义错位）

固定陪衬：底部通栏进度条（实时反映 `p`）、左侧 `01 / 02 / 03` 序号、中央 `SCROLL TO EXPLORE`（仅 `p===0` 显示）。

### 4.3 三段的具体文案映射

| 段 | eyebrow | 主标题（全大写） | 描述 |
| --- | --- | --- | --- |
| 首屏 `p=0` | `00 / FIRST MEETING` | `DESIGN`<br>`WITH`<br>`FEELING.` | 别急着看作品，先认识一下——一个对世界保持好奇的设计师。 |
| 节奏 1 | `01 / SELECTED WORK` | `MADE`<br>`IN`<br>`THE SOFA.` | 陷进沙发里，把想法一点点做成能用的东西。 |
| 节奏 2 | `02 / THE CARDS` | `RAG`<br>`WEB`<br>`AGENT.` | RAG、网站、Agent，三张卡片，三次把想法落地。 |
| 节奏 3 | `03 / INFINITE` | `STILL`<br>`ROLLING.` | 工具会一直变，好奇心不会——所以我还在往前滚。 |

主标题全部两到三行硬换行，还原参考图 `DESIGN / WITH / FEELING.` 的堆叠方式。

> **主标题最长一行必须 ≤ 9 字符**（v3 新增约束）。这不是审美偏好，是排版硬约束：
> 字号是流式的（`clamp`），字体回退在 iOS / Android 上都落不到 Impact（两端都不自带），
> 最坏情况是系统无衬线的大写宽高比 ≈0.6em/字符。收尾那句原本是 `SCROLLING.`（10 字符），
> 在 721–800px 与移动端会顶破容器、被 `overflow-wrap` 从词中间劈开。
> 改成 `ROLLING.` 后各宽度都留出 10% 以上余量 —— 而且「还在往前滚」本来就比
> 「还在滚屏」更贴那句中文。这条约束已进 `showcase_dom_check.js`，改文案时会被挡住。

### 4.4 文案避让视频构图（v2 需求）

「要根据主视频来区分板块」落到具体行为上 = **文案位置随该板块画面里主体的位置避让**，而不是四段文案都钉在同一个位置只换内容。依据四张分镜的构图定：

| 段 | 分镜主体位置 | 可用负空间 | 文案落位 |
| --- | --- | --- | --- |
| 首屏 | 人物在**右**，左手向左伸出 | 左侧大片净墙 | **左侧垂直居中** |
| 节奏 1 | 人物＋笔记本在**右**，沙发在右下 | 左侧大片净墙 | **左侧垂直居中** |
| 节奏 2 | 三张卡片占据中部与下部，主体**居中** | 上方与左右边缘 | **上部靠左** |
| 节奏 3 | 人物**居中**，碎片向上飞散 | 左下角 | **左下角** |

实现方式：每个 `.copy` 用 `data-pos` 声明落位（`left` / `top` / `bottom`），CSS 把 `data-pos` 映射成具体的 `left/top/transform`。**调位置只改 HTML 上的一个属性值**，不碰 CSS。

> 素材说明：以上落位是按**分镜关键帧**推导的占位值。真实 mp4 到手后，若某段主体其实在另一侧，改对应 `.copy` 的 `data-pos` 即可。

## 5. 验收标准

> 全部可验证。因用户要求不自动开浏览器，标注 `[手工]` 的项由用户在浏览器确认。

**叙事与排版**
1. `[手工]` 页面呈现 4 段文案（首屏 + 3 节奏点），切换时与主视频对应时间区间同步。
2. `[手工]` 主标题为大写压缩无衬线；**在 ≥1200px 视口下**字号 ≥ 5 倍描述字号（此时 `9vw ≥ 108px`，实测 ≈ 7×）；eyebrow 带明显字距。
   > 之所以限定视口：主标题是 `clamp(3.5rem, 9vw, 7.5rem)` 的流式字号，而描述固定在 15px。
   > 窄视口下主标题必然相对变小，这是任何流体排版的正常行为。硬要在 720px 也保 5 倍，
   > 只能把主标题钉在 80px 以上 —— 实测那会让 `SCROLLING.`（10 字符）横向溢出容器，
   > **用真实的溢出 bug 换一个数字指标不划算**。
3. 全站颜色仅取自参考图色板（暗青灰背景 / 奶白文字 / 暖沙金强调），**无 `#000` / `#fff`**。
4. 720px 以下视口，参考图的非对称双栏**堆叠为单列**，主标题字号按 `clamp()` 缩小且不溢出。

**滚动驱动**
5. 滚动进度 `p ∈ [0,1]` 与 `document.documentElement` 滚动位置线性对应。
6. `main.currentTime === p × main.duration`（允许一帧内阻尼误差）。
7. **向上滚动时主视频倒放**（`currentTime` 递减），无卡顿跳帧。
8. `p === 0` 时 main 的 `currentTime === 0`。
9. `p >= 0.98` 时 outro 透明度升至 1，main 仍停在最后一帧。
10. 任意两段切换的过渡时长为 `0.5s`，无硬切。

13. `[手工]` 触屏设备或 `prefers-reduced-motion` 下 intro 回退为自动循环播放，首屏不出现死画面。

**背景恒定（v2）**
