# 批量上传与上传校验

## Goal

把"一次只能传一份、问题留到后台 worker 才发现"的体验改成：批量选文件、前端逐文件预校验去重并提示，后端单请求多文件落库并做权威校验（含图片型 PDF 快速失败），错误明确、合法文件不因个别坏文件而失败。

## Requirements

1. 前端：一次多选（.txt/.md/.markdown/.pdf），上传前按文件逐项校验（类型、大小、文件名合法、与现有库判重），不合规项在界面列出来，可继续上传合规项。
2. 后端：提供批量上传接口（多文件 multipart），沿用并强化现有校验；校验失败返回含逐文件结果的结构，而非整批 500/413。
3. 文件名规范化：后端取 basename（防路径穿越）、拒绝控制字符与 `\/:*?"<>|`、长度 1..255（库列 `models/document.py:18` 为 String(256)）、去首尾空白/点；不合规返回明确错误码；前端做同规则预检。
4. 重复文件（**内容哈希 SHA-256**）：`documents` 新增 `content_hash` 列 + 迁移；后端对每次上传算哈希，与本人已有文档（哈希非空者）比对，命中则拒重并提示"内容已存在：<原文件名>"；DocumentOut 暴露 `content_hash` 供前端预检；存量空哈希文档按文件名粗查（已知限制）。
5. 图片型 PDF 不空转：上传时即检测纯图片 PDF（无文字层）；此类文档**正常保存**、进入**新增「不可检索」状态**（不复用 failed），**不投递 worker 切分任务**，供预览与将来 OCR。当前无此检测会拖到 worker 才 failed（`worker/main.py:88-90`）。
6. 保持单文件 ≤ 20MB 上限与类型白名单；兼容删除既有单文件行为不回归。
7. 状态机新增一个终态（如 `no_text`，英文枚举名在设计定稿）：`uploaded → processing → ready / failed` 之外的单列终态，不影响现成流转。

## Acceptance Criteria

- [ ] 一次多选上传多份文档，均成功入库入队；列表出现全部新记录（含失败/拒绝项的逐条中文原因展示）。
- [ ] 批量中含 1 份不合格文件（类型/大小/重名/空）时：该文件被拒绝并给出具体中文原因，其余文件正常入库。
- [ ] 同一文件改名重传 → 被判重拒绝；同名不同内容 → 正常入库。
- [ ] 纯图片型 PDF：上传成功、状态「不可检索」、不投递切分任务、列表可见可预览。
- [ ] 上传界面不裸 alert：用内联/列表形式把每份文件的校验结果呈现给用户。
- [ ] 文件名含非法字符/超长 → 前端预检提示 + 后端同样拒绝。
- [ ] 状态机与前端类型/徽标都能正确展示新增「不可检索」终态，且 old 数据不受影响。
- [ ] 迁移后存量数据可读、旧文档 content_hash 为 NULL 不报错。
- [ ] 既有单文件上传、删除不回归。

## Out of Scope

- OCR、断点续传、真实上传进度条。

## Notes
