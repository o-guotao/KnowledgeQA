## SQLite 本地模式踩坑（2026-08-27，3 个反复才跑通）

sqlite 模式与 postgresql 的 5 处不兼容，逐个修复：

1. **`reap_stuck_running` 用了 Postgres 专有函数**（left/now/make_interval）
   - 现象：worker 启动即崩，`near ">": syntax error`
   - 修：按 db_backend 分支，sqlite 用 substr/datetime('now', '-N seconds')

2. **`claim_task` 用了 FOR UPDATE SKIP LOCKED**（sqlite 不支持）
   - 现象：同上语法错误
   - 修：sqlite 模式改 SELECT-then-UPDATE（单 worker 无竞态）

3. **SQLAlchemy 隐式 Uuid 类型在 sqlite 读回报 `value.hex` AttributeError**
   - 现象：`AttributeError: 'str' object has no attribute 'hex'`
   - 修：`storage_compat.UUIDType()` 按 backend 返回，sqlite 用 `String(36)`

4. **sqlite 驱动不认 uuid.UUID 对象**
   - 现象：`Error binding parameter 1: type 'UUID' is not supported`
   - 修：写 `SQLiteUUID(TypeDecorator)` 自动 uuid<->str 转换（process_bind_param/process_result_value）

5. **storage_compat 重写时漏了 get_vector_type 函数**
   - 现象：`ImportError: cannot import name 'get_vector_type'`
   - 修：补回 get_vector_type

**教训**：跨 DB 兼容改造必须从入口（db.py）到模型（UUID 类型）到 SQL 函数（now/interval/locking）全链路考虑，逐个验证。每改一处用 `python -m compileall` + 启动探活，避免一次改多处难定位。
